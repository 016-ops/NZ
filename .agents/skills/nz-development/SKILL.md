# NZ 项目开发规范

本 skill 适用于所在仓库的开发工作。所有路径相对项目根目录；先阅读项目入口规则及与任务相关的现有代码、架构说明和交接记录。

## 技术栈约束

- 网页端统一使用 React + TypeScript，组件和业务代码使用 `.tsx` / `.ts`。
- UI 统一使用 shadcn/ui，优先复用项目已安装的组件与样式约定；缺少组件时按 shadcn/ui 方式补充。定制组件以现有 shadcn/ui 基础组件组合实现，保持视觉与交互一致。
- 后端统一使用 Python + Django。使用 Django 项目、应用、路由、模型及迁移机制组织业务实现。
- 数据库统一使用 MySQL。通过 Django ORM 和 migrations 管理数据结构；数据库测试使用 MySQL，不能以 SQLite 的测试结果宣称 MySQL 已验证。
- 版本及依赖以项目已有配置和锁文件为准；缺少配置时按任务需要补齐。数据库连接信息从环境配置读取，不把密码写入代码或交接文档。

## 中文代码注释

- 项目所有代码都必须有详细的中文注释，覆盖前端、后端、数据库迁移、SQL、脚本和测试代码。
- 文件或模块说明职责；类、函数、方法及 React 组件说明用途、主要输入、输出或返回值，以及副作用和异常行为（如适用）。Python 使用中文 docstring，TypeScript 使用中文 JSDoc 或块注释，其余文件使用对应语言支持的注释语法。
- 关键业务逻辑、分支条件、边界处理、权限校验、事务、并发和幂等处理必须解释业务含义、实现原因与约束；测试注明验证场景及预期行为。
- 注释必须与代码同步更新，准确解释实际行为；不能只翻译变量名或重复语句，也不能以外部文档代替代码内注释。
- 修改现有代码时，检查并补齐涉及模块的中文注释；发现其他存量代码未符合要求时，在交接文档中记录待补齐范围，不得宣称已完成全项目注释整改。
- 交付前检查本轮涉及代码的中文注释覆盖与准确性，并在交接文档的验证记录中说明检查结果。

## 现有实现与新规范的衔接

发现旧实现采用其他技术栈时，明确记录差异。新增与改动功能以本规范为目标；确需迁移时，评估受影响接口、数据和启动流程，并在当前任务范围内执行。创建或维护本 skill 本身不包含业务系统迁移。

无法在本轮完成的技术栈迁移必须写入交接文档的“未实现”和“阻塞”部分，不得把现有旧实现描述为已经符合本规范。测试环境或数据库不可用时，记录实际限制与未验证范围，不能默认为通过。

## 每次修改的交接要求

每个修改批次结束、向用户交付结果前，必须在项目 `docs/delivery/` 下新增或更新对应的 Markdown 交接文档。范围包含功能、修复、重构、配置、数据库迁移和文档/skill 修改；中途受阻的批次同样需要记录。记录以实际实现及验证证据为准。

优先沿用任务已有交接文档；没有对应记录时使用 `YYYY-MM-DD-任务简述.md`。不同任务使用独立文件，同日同名冲突时加序号。保留既有交接历史，不覆盖其他任务的记录。

填写 [assets/delivery-template.md](assets/delivery-template.md)，至少详细记录：

1. 本轮目标、范围、日期，以及涉及文件或模块。
2. 已实现功能：用户可见行为、入口、主要实现、接口或数据变化。
3. 未实现内容：原定目标中尚未完成的事项、当前完成程度、后续步骤。
4. 当前阻塞：具体原因、证据、影响范围、解除条件和下一步；没有阻塞时明确写“无”。区分未完成工作与真正的阻塞。
5. 验证记录：实际执行的命令或步骤、环境、结果及未验证项。
6. 接手说明：必要的启动/配置/迁移步骤、风险和回退方式；不适用时明确说明。

没有未实现内容时明确写“无”，不能省略章节。完成交接文档后检查文件存在、内容与实现一致，并在最终交付回复中提供文档路径。
