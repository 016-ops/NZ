# M3：大厅房间与实例契约本地实现

日期：2026-10-13。这里的房间测试采用 `test-arena` 合成地图和 4 席测试规则；没有宣称当前逆战任何模式的人数上限。

## 已实现

| 批次 | 本地实现 | 测试与状态 |
|---|---|---|
| M3.1 | 共享持久化房间列表、刷新和当前成员查询 | HTTP/领域读取，最多返回 100 房间 |
| M3.2 | 创建/加入/退出/准备、唯一席位、单房绑定、房主迁移、地图配置、revision | 并发抢席位、重复加入、房主退出、旧 revision 拒绝 |
| M3.3 | 分配 reservation/match/instance/epoch、冻结装备/配置/玩家安全版本 | 分配后仍 STARTING，不凭进程存在返回游戏就绪 |
| M3.4 | 测试节点身份和当前局授权契约 | 仅合成 host 注入；真实基本战斗未实现 |
| M3.5 | 取消分配、就绪/活跃租约、失联失败、会话过期清理、离开标记资格 | 20 轮开始/取消、超时回收、封禁不会误清其他成员 |
| M3.6 | 回环访问的实际 HTTP 控制 API | 不同家庭网络和原生网络路径未测 |
| M3.7 | 两个房间的成员/退出隔离 | 本地领域测试；不代表两套真实地图互动 |

代码：`revival/rooms.py`、`revival/schema.sql`、`tests/test_control_plane.py` Rooms、`tests/test_http.py`。数据库事务和唯一约束控制并发，玩家请求不能获得节点结算令牌。

开始时冻结规则/目录、席位、账号安全版本和未到期装备。房间进入 ALLOCATING；30 秒内没有 host 就绪则 FAILED 并回到 OPEN。活跃测试节点必须以独立节点凭据、match_id 和 epoch 续租；旧 epoch、过期租约及玩家 token 均拒绝。

`test_host_ready()` 是只在测试模式允许的 Python harness，**没有 HTTP 路由**，不执行地图或战斗。它不能替代生产 host 的真实地图/网络/规则健康检查。默认当前客户端没有已确认地图，创建和就绪调用会明确拒绝。

## 未实现与阻塞

- 真实客户端大厅/频道、房间分页/过滤、房间密码/邀请、地图/难度协议。
- 当前国服的原生实例进程启动、端口分配、可达地址与身份握手。
- 出生、位置/动作、弹药、碰撞、攻击、伤害、死亡/复活和可信战斗事件链。
- 双客户端共同作用于同一个权威对象/事件，同 NAT、跨家庭网络和多真实房间隔离。
- 房主退出/重进是否符合当前客户端原版规则；当前清理行为只是明确的本地测试策略。
- 生产节点断网下的制裁确认、消息撤销、进程/端口资源回收和容量保证。

阻塞项为 M1 原生运行/协议证据与隔离双端条件。HTTP 返回一致房间数据不是游戏画面同步证据。M3 的真实多人阶段退出条件未通过。

## 验证、恢复与下一步

自动化覆盖共享成员、并发最后席位、一个玩家一房、revision/准备/开始冻结、取消/失联、旧节点拒绝、双房隔离以及地图中封禁的本地授权传播。节点测试标记 TEST_PROFILE，未启动游戏程序或占用任何原生 UDP 端口。

进程重启后的旧 reservation 由租约回收，不能给新局复用旧 epoch。持久房间数据可查询，清理不会给旧实例授权新的身份。后续先实现有证据的真实 host 接口与就绪探针，再做双端共同对象战斗验收。
