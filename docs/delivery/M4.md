# M4：资产、库存与合成结算本地实现

日期：2026-10-13。本地测试目录为 `test-only-v1`，币种 NZ/GP 和 test-rifle/test-token 是合成规格；未知国服币种/物品映射仍拒绝。

## 已实现

| 批次 | 本地能力 | 实现 |
|---|---|---|
| M4.1 | 显式版本目录、整数范围、未知资源/无效数量/期限拒绝 | `config/test-profile.json`；默认当前样本目录为空 |
| M4.2 | 统一资产服务、钱包版本、独占/叠加/永久/限时实例、不可改写流水 | 同事务更新钱包/库存/账本/outbox/命令审计 |
| M4.3 | 本地库存、装备所有权/槽检查、过期校验、消耗与下局装备快照 | 本地 API/页面；原客户端仓库未接入 |
| M4.4 | 管理员增量发放/扣减、单人预览、分离权限/限额、大额 MFA、冻结批次、补偿/复核 | 同键同请求返回原结果，同键改请求冲突 |
| M4.5 | 服务端目录定价购买、余额/发货原子性和购买流水 | 不能由客户端改变价格，独占/满仓失败全回滚 |
| M4.6 | 可信合成节点的按局/epoch/资格结算、冻结奖励规则、结算唯一约束 | 客户端不能提交胜利或奖励金额；重复结果只到账一次 |
| M4.7 | outbox 失败/退避/确认、通知与资产分离、重启后查询和幂等重试 | sender 必须以 event_key 去重，未经确认不标同步成功 |

代码：`revival/assets.py`、`revival/service.py`、`revival/schema.sql`。操作记录关联 actor/target/reason/source；流水保存前后数量/余额、实例 ID 和期限/绑定/钱包版本细节；页面可查记录。离线账号正常持久化，下次本地登录读取已提交状态。

资源管理员单个请求币种增减总量限 10,000，不能通过多条变化规避限额。Owner 大于该阈值的发放、批量和补偿需要当前密码与新 MFA 验证；绝对余额设置和任意 SQL 接口未开放。

批量一次最多冻结 20 个唯一目标，目标失败用 savepoint 回滚，其他成功目标不重发。同键重试返回原批次结果；重试失败子项必须固定为失败 ID 列表并使用新键。误发正向货币可关联补偿；余额已花费或物品需追溯时写 MANUAL_REVIEW，不强行制造负余额或删除历史。

## 未实现与阻塞

- 当前国服 NZ/GP 编码、字段宽度/范围、全部物品 ID/期限/装备槽与价格。
- 原客户端仓库/商城/流水、在线即时刷新/离线重登投影及对局装备生效。
- 原版耐久、续期、邮件/待领取、Boss/波次/宝箱和真实掉率/参与资格规则。
- 国服真实通关/失败/退出/崩溃结算来源、结算 UI 与可信原生节点集成。
- 大批次持久工作队列、UI 批量预览/确认、物品补偿自动溯源和人工复核处理页面。

默认配置没有任何已确认币种或物品，不能把合成 NZ/GP 写成当前游戏已验证资产。真实同步未实现时 outbox 保持待发送，页面明确 `PENDING`/`UNIMPLEMENTED`。没有将通知失败当作重新发放资产的触发器。

## 测试与恢复

自动化覆盖 10 次重放、同键内容冲突、A/B 隔离、并发发放与购买、扣款后发货失败全回滚、审计故障全回滚、响应丢失后的重试/重启、未知/负数/溢出/无效期限、独占/叠加/满仓、到期、非本人实例、outbox 失败重试、合法补偿/余额已花费复核、批次部分失败、合成结算与伪造/过期来源拒绝。

首次失败及修复记录保留在 `evidence/failures/`，最终测试结果见 `evidence/automated-tests.json`。合成结算测试不计入真实通关通过数。

停止服务并在线备份到新文件；回退代码应兼容现存账本。不要覆盖运行数据库或以旧快照抹掉资产、制裁和 outbox。真实目录/协议证实后逐个增加物品类型，用原客户端在线、重登、重启交叉验证。
