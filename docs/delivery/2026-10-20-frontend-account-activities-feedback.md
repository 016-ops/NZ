# 本轮开发交接：两端账号、独立活动与反馈中心

## 基本信息

- 日期：2026-10-20（北京时间）。
- 目标与范围：网页与 Tauri Launcher 共用账号表单、玩家商城隐藏、活动中心/独立详情、后台活动模板、带私有截图的反馈工单。
- 技术栈：沿用 React + TypeScript + shadcn/ui；后端合同由同批 Django 开发接入，未新建 Electron。
- 涉及模块：`portal-app.tsx`、`App.tsx`、`email-access.tsx`、`native-launcher.tsx`、`platform-pages.tsx`、`operations-center.tsx`、`operations.tsx`、`lib/api.ts`、`lib/platform.ts`；新增 `admin-step-up.tsx`、`character-onboarding.tsx`、`feedback-pages.tsx`、`catalog-item-picker.tsx`、`operations-campaign-presentation.tsx` 及相关测试。
- 视觉由父任务负责全局样式、原创主视觉和道具展示目录；用户最终改回原深蓝灰、暖金主题，本批已恢复两端文档 dark 和 Launcher 外壳 dark，使 body 下弹层与页面主题一致。

## 已实现功能

1. 玩家注册与登录共用 `EmailAccess`。注册字段为邮箱、密码、确认密码、昵称、邮箱验证码；发送/注册均不再传邀请令牌。注册和找回密码均须本机确认一致后才调用接口，确认值不发后端/本机桥/幂等正文，切换模式或成功时清空。成功注册后立即以仍驻内存的密码登录。注册已成功而自动登录失败时，明确提示账号已创建并引导登录，避免让用户重复注册。
2. 旧 ACTIVE 且邮箱已验证的账号缺角色时，两端与旧工作台先展示补建昵称入口；成功调用 `character.create` 后回读本人信息。未完成角色时不能在 Launcher 点击启动。旧 PENDING 仍需管理员批准，迁移/登录/补验/密码恢复均不自动批准；邮箱未验证不能补角色。
3. 管理员密码与邮箱两阶段登录：`/api/admin/login-code` 后调用 `/api/login`。Owner 命令收到 `REAUTH_REQUIRED` 时触发统一邮箱验证弹窗，挑战绑定冻结的原业务 payload 和元数据；认证证明仅用于最终命令，不写入幂等副本或浏览器存储。弹窗显示中文动作、目标摘要和与邮件一致的操作指纹，不显示完整payload或密码。取消时原操作不提交。
4. 玩家 Web、Launcher 和旧控制台的商城购买入口、渲染与调用均已移除。管理员商品运营保持可用，冻结游戏协议目录未改写。
5. `/activities` 为活动汇总；`/activities/<slug>` 读取真实 `campaign-detail`。Web 内导航保留内存会话并支持前进/后退，Launcher 保持单 URL 内存详情导航。独立详情展示北京时间、真实进度、签到、普通手动领奖与榜奖自动发放状态。
6. 运营端增加独立 presentation 配置：slug、标题、摘要、受控主题、公共封面上传、纯文本/真实奖励/真实排行榜模块及排序。使用独立 presentation revision；发布后锁定 slug，不改奖励冻结定义。嵌入榜单固定当前活动，使用真实地图/人数/难度筛选和空榜状态。
7. 反馈中心仅在已登录玩家工作区和 Launcher 中展示业务内容；后台 Owner/用户管理员可以回复及更新四态，审计员只读，资源管理员没有反馈入口。支持列表筛选分页、详情、回复、关闭只读、已解决后回复重开的提示。
8. 每条反馈总计最多 3 张、单张 5 MiB 的 PNG/JPEG/WebP。正文先创建，图片逐张使用稳定 upload_key 独立上传；失败重试保留原工单和未完成文件，避免重复正文/附件。已上传图片通过当前身份取 Blob，临时 object URL 在卸载时撤销，不以公开地址绕过权限。图片上传后回读 revision，避免随后回复使用旧版本。
9. 道具展示调用父任务的 `ItemArtwork` 和 `itemName`；管理员发放/活动配置改为中文道具选择，资源键保留在组件值中，同名目录以版本序号区分。普通账号/库存状态中文化，未知英文错误码由 `ApiError` 转为中文；原机器码仅用于程序分支及折叠诊断。
10. 新账号、模板、反馈、补角色和手写道具发放操作已接全局操作提示。通用 `CommandButton` 的全局结果弹窗由父任务继续整合，避免双方修改同一函数。
11. 导航及页面入口统一为“活动”，接口返回的实际活动标题保持。列表、详情和后台预览在没有自定义封面时共用主题预置图：default 双人主视觉、tactical 主武器分类、anniversary 装备分类。自定义公共封面优先，后台“使用模板预置封面”恢复模板图。Launcher 严格只允许这三张完整匹配的打包资源直接显示；其他未知地址仍不直连或代理。
12. 最终预览修正资源代码展示：首页移除装饰地图 ID；榜单、开放白名单和榜奖范围仅以“待确认难度 · 选项 N”显示未核实难度，真实 ID 保留在折叠技术详情及表单值。管理员仓库实例/资源码、商城商品/币种码和共享详情中的原始槽位/状态默认折叠；未知币种、模式及槽位使用待确认文案，不猜测正式名称。原命令字段、库存实例和选择值未改写。

## 接手与回退

- 本机预览：Web 使用既有 8875；Launcher 无能力令牌的 5174/launcher 仅用于布局/表单预览。
- Web 图片接口：反馈上传 `/api/feedback/{ticket_id}/attachments`，鉴权读取 `/api/feedback/attachments/{id}`，管理员封面上传 `/api/admin/media`；上传使用 multipart 的 file 与 upload_key。
- 本机桥：`account` 固定四种 operation；`feedback-upload` 有界 base64 上传；`feedback-image` 有界 base64 读取。界面不能指定远端路径、地址或业务凭据。
- 数据库：前端不创建迁移；配套认证/反馈/活动展示迁移由后端批次管理，部署前必须与当前分支一并执行。
- 回退：前端构建与本轮对应后端合同应一起回退，不能将旧邀请码/MFA 页面混接新邮箱挑战接口。无能力令牌时保持禁用，不通过预览绕过本机桥。
- 下一步：父任务完成最终深色样式与通用结果弹窗后统一构建，继续隔离环境已登录工单、附件、角色补建、管理员邮箱挑战与活动深链验证。浏览器公开注册截图位于 `evidence/portal-ui-v2/web-register.png`，属于配色调整前的中间状态，不能作为最终视觉验收图。
