# M2：独立账号与管理后台本地实现

日期：2026-10-13。实现类型是本地 Web/领域服务与 HTTP 集成，原客户端首登尚未接入。

## 已实现

| 批次 | 本地能力 | 实现 |
|---|---|---|
| M2.1 | 默认关闭公众自由注册；令牌哈希、次数、有效期、撤销；待审核账号 | `revival/service.py`、邀请/账号唯一约束、注册页 |
| M2.2 | 密码慢哈希、正确/错误凭据区分、独立会话、版本撤销、内部游戏 ID 映射 | 玩家与管理员身份/会话分离；管理员需要 MFA |
| M2.3 | 独立昵称/角色、初始化唯一约束、零余额钱包；重试不重复初始化 | 本地昵称规则标明 `LOCAL_EQUIVALENT`，不伪装原客户端昵称规格 |

| M2.5 | 用户列表/搜索/详情、邀请/撤销、批准、停用/激活、重置、踢会话、临时/永久封禁、指定解封、审计 | `admin/` 页面、服务端权限矩阵、只读审计触发器 |

管理员采用密码加 TOTP、15 分钟会话；玩家会话 60 分钟。新登录撤销旧玩家会话并释放本地席位。所有制裁检查独立于账号激活状态，解封一条不会移除另一条有效制裁。

本地用户与后台 ID 是服务自己分配的映射，不绑定 QQ，不保存腾讯凭据。初始 Owner 由交互命令创建，普通注册不能获得管理角色。第一版没有修改/停用管理员的接口，因此不能通过普通流程停用最后一个 Owner；其他后台角色的授权逻辑已做负面测试，管理员生命周期管理待后续补齐。

## 安全与边界

慢哈希为标准库 scrypt：N=32768、r=8、p=3，随机 16 字节盐；选择见 ADR-002。MFA 密钥和会话验证数据属于私人数据库，后台查询/审计不返回密码或 token。数据库与 MFA 资料依赖操作系统用户文件权限保护，尚未交付密钥保险库或多主机管理。

HTTP 默认只监听 `127.0.0.1`，检查 Host/Origin、要求 JSON 和自定义请求头；令牌只存在页面内存；无跨域授权、无自动保存密码。接口限制体积/并发/速率，页面用文本节点输出内容。

## 未实现与阻塞

- 当前国服凭据/挑战格式、游戏 ID 表达范围与映射到真实协议。
- 从真正空库通过原客户端首登昵称、角色和初始资源流程。
- 原客户端区服/大厅、两端同时登录与真实多账号隔离。
- 封禁到真实游戏节点的确认/失败传播和游戏内踢出；本地 outbox 中保持待发送。
- 管理员增删改、多因素恢复、HTTPS 私网部署和资产同步等实机管理验收。

这些任务依赖 M1 协议/实例证据和隔离实机。本地审批不会被描述为“游戏首登通过”，本地 READY 角色不会跳过正式首登后被算成原版复现。

## 测试与回滚

测试包含 10 次并发使用单次邀请、同键重放、新账号隔离、会话撤销、永久/限时/多条制裁、服务重建后的状态保持、玩家/不同管理员角色直调接口拒绝，以及真实 HTTP 的 CSRF/Host/Origin 负面用例。结果见 `evidence/automated-tests.json`。

服务源码回滚不恢复旧安全数据；停止服务、用 SQLite 在线备份建立新的恢复分支，核对账号安全版本/制裁/outbox 后再重新开放。已撤销会话不能通过恢复旧快照自动复活。
