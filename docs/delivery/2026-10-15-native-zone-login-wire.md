# 当前客户端：单区服目录与登录响应研究

## 范围与实现

本批继续独立邮箱登录接入，原始 `nz/` 不写入。所有启动均使用已恢复的独立工作副本、短时自有 Job 和回环监听器。DEV 邮件验收账号由正常 API 登录、兑换独立游戏票据，探针结束后撤销来源会话；本批没有追加真实邮件。

`tools/native_email_boot.py` 通过显式选项串联当前协议：认证与挑战、换钥、GEO 测速响应、唯一服务器目录、第二条连接的独立认证、网吧标识通知、Zone 登录请求。`--capture-zone-sequence` 限制第二连接最多八条额外应用帧、整个序列十五秒，所有原始帧只写私人证据目录。未认识的消息只记录有界包头，不能作为业务成功或自行发送响应。

`--serve-zone-login` 另行启用当前 DLL 已核对的 41 字节 `A001` 研究响应，并要求 CLI 同时使用已验证 DEV 邮箱身份。相同连接重复登录不再次回复。当前 `Result=0x8100` 正常分支来自固定指纹客户端的实际代码；不是从其他区域版本复制。该分支后续发送 `FF05` 的代码已定位，但运行结论必须以实收包为准。

固定兼容规则为 `cn2020-zone-login-success-research-v1`：主/子频道各 1，ServerTime 为 0（当前代码明确跳过时间校准），两种币值、免费道具数、新手标记和区域为 0。这些数值用于消费路径研究，没有投影真实钱包或角色，没有赠送资产，不能作为生产业务规则。客户端其他能力开关继续保持未完成状态。

随后增加 `--serve-player-define`，它必须依赖已开启的研究登录回应。当前实收 `A204` 为仅8字节包头，当前元数据没有该命令的正文联合体分支；解析器严格拒绝非空正文。`A205` 的当前消费者已证在 `Result=0x8100` 且 `DataLen=0` 时跳过未知格式内容并执行完成回调，因此独立定义 `cn2020-player-define-empty-research-v1`。此固定14字节响应已通过当前 DLL 的正文/全包/完整host往返；它不读取或清空真实玩家设置，也不构造未知的非空版本数据。正常游戏消费和后续完成状态仍需逐项观测，不能从编码成功推断。

## 验证

- boot18：当前客户端消费 52 字节测速响应，返回 40 字节服务器目录请求。
- boot19：消费仅含一条服务器的 70 字节目录响应，建立第二条 TCP 连接并通过认证、挑战、换钥；收到 11 字节 `1250` 网吧标识通知。
- boot20/21：使用真实已验证 DEV 邮箱身份复现完整目录路径，在通知后收到 26 字节 `A000` 登录请求。当前 DLL 解包到完整 host 结构再打包，逐字节一致。十五秒内没有发送登录响应；此处等待超时不是客户端拒绝证据。
- boot22：实际发送该 41 字节 `A001` 后收到 `A204` 和预期的 12 字节 `FF05`，确认当前成功初始化分支已执行。后续安全组件通知正文未公开或解释；八条采集上限触发主动关闭后出现尚未支持的重连帧，不应当作之前登录响应被拒绝。后续工具改为采集结束后保持连接至主探针清理，避免人为关闭制造此干扰。
- 当前 DLL 离线验证：11 字节通知、26 字节登录请求、41 字节研究登录响应均精确往返；响应正文单独打包为 33 字节，与全包一致，完整 host 比较、保护哨兵及 Job 清理均通过。
- CLI 边界回归：没有明确采集模式或已验证邮箱身份时，登录响应选项在读取凭据、启动客户端前被拒绝。

详细证据见 `evidence/aliyun-native-launch-summary.json`、`aliyun-native-zone-login-consumer-static.json`、`aliyun-native-zone-login-response-offline.json` 和 `aliyun-native-zone-login-response-tests.json`。公共报告不包含网吧密钥、邮箱凭据、会话令牌或原始认证包。

## 未实现与阻塞

角色与玩家资料通知、真实余额和库存投影、首登昵称页面与角色选择、稳定大厅、原生地图加载、战斗与结算、断线恢复和双端验收仍未完成。登录请求和固定响应编码通过不能替代这些关卡。

主要依赖是当前版本玩家通知的必需字段、合法角色资源映射与大厅初始化顺序。未知结构或结果码不得按 PH 模板填充；继续用当前元数据、当前 DLL 和受控实际请求响应逐项验证。原生房间节点入口和最小资源包也尚未验证，详见单房间服务器交接。

## 恢复与接手

运行时原始记录仅放 `evidence/private/`。一次只启动一份探针，正常或异常退出都需要确认自有进程、捕获线程和连接结束，以及三份临时配置通过 `NativeConfigGuard` 恢复。恢复遇外部编辑时保留现场，不强行覆盖；四个原件关键文件另行核对，不宣称本批重哈希了全部原目录。

本批没有业务数据库迁移或资产写入，不需要回退玩家数据。公开工具和协议适配仍为研究入口；不能因其存在将 DEV 的原生启动、角色、大厅或节点 readiness 改成已完成。
