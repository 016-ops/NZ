# 本轮开发交接：控制面技术栈迁移、UI 优化与测试管理员

- 日期：2026-10-14（北京时间）。
- 目标与范围：按照 nz-development 将本地控制面迁到 React + TypeScript + shadcn/ui、Django 与 MySQL；保留业务和 HTTP 合同，提供只读 SQLite 导入工具。按用户后续要求补充中文注释、优化前端，并建立两个分别支持固定测试码和免登录验证码的测试管理员。

## 已实现功能

1. **MySQL 与事务**：显式映射旧业务表和稳定逻辑列，增加的内部主键不出现在接口和导入结果。采用 InnoDB、utf8mb4、严格模式及二进制排序规则。Django migrations 初始化 schema、部署锁、关系和检查约束；六个触发器禁止更新或删除审计及资产历史。所有业务通过 `atomic()` 和固定锁记录 `select_for_update()` 串行执行；预览及批量子项使用保存点，余额、库存、流水、幂等、审计与 outbox 同事务。
2. **业务迁移**：账号、邀请、角色、权限矩阵、制裁、会话替换/撤销、TOTP 防重放、房间席位/修订/冻结、节点身份/租约、购物/消费/装备、补偿/人工审核、批量部分失败、合成结算及 outbox 重试沿用旧行为。运行时业务 SQL 和 SQLite 数据层已移除，SQLite 只用于导入源及迁移夹具。
3. **HTTP 与生命周期**：Django 接管原路由、JSON 和业务错误。中间件处理 Host/Origin、重复字段、非有限数字、64 KiB、限流及安全响应头。Waitress 回环单进程、16 工作线程；严格解析器在解码前拒绝 Transfer-Encoding，超限小正文有界排空后返回 JSON 413。对大于 128 KiB 的超大正文立即拒绝，客户端可能先收到连接关闭。独立维护进程每五秒清理期限与租约。前端同源，公共静态资源启用 gzip，凭据响应不启用压缩。
4. **独立实例与命令**：已有 MySQL 程序运行仓库 `runtime/mysql` 实例，监听 `127.0.0.1:3307`，不修改系统 MySQL 服务。当前、合成和自动化测试库分离；私有环境配置读取凭据。脚本支持初始化/启停/状态、迁移、Owner 初始化、服务与维护。保留 `python -m revival` 命令代理，旧文件 `--db` 参数明确提示迁移。
5. **只读导入**：`manage.py import_sqlite` / 兼容命令支持 `--dry-run`，只接受 schema v1、同 profile 和空业务目标。按依赖顺序单事务保留业务 ID、密码、MFA、安全版本、期限、账本及幂等记录，核对行数、关联及逐记录数据。失败或 dry-run 全回滚；不改变源 SQLite，不输出凭据。
6. **备份**：在统一写事务边界执行 MySQL 一致性逻辑导出，拒绝已有目标；临时恢复库实际恢复并逐表摘要核对，清理恢复库后才报告成功。没有覆盖式自动恢复。
7. **React 页面**：Vite、TypeScript、Tailwind 与 shadcn/ui，提交 npm 锁文件；保留登录/受邀注册、用户、邀请、资源预览确认、房间、目录、审计和同步入口。统一表单、提示和确认框；每个表单有独立 label ID。会话仅在内存；同内容失败重试保留幂等键，并按该键冻结最终 HTTP 正文，避免期限重新计算造成冲突。
8. **UI 优化**：保留 NZ 标识及中文业务入口，改为登录/注册切换、工作空间导航、真实业务指标、账号工作流、中文表格与折叠技术详情。中性背景与绿色语义主色，明暗主题、窄屏布局、可见输入边界及 reduced-motion。favicon 复用 Lucide Gamepad2。数据切页进行形状检查并隔离慢响应，修复浏览器验收发现的白屏。
9. **两个测试账号**：用户要求的固定码测试管理员与指定免码登录管理员分别创建。例外均由服务端私有环境配置限定账号 ID、数据库和 synthetic profile，不能由客户端传入开关。免码账号仅登录免 MFA，高风险操作继续要求再认证；其他管理员保留正常 TOTP。六位密码只在专用测试创建入口允许，普通注册/重置/Owner 规则不改变。创建时数据库写入和配置安装失败会回滚，拒绝覆盖已有账号配置。本交接不记录任何明文凭据，分别保存在忽略的 `runtime/test-admin.json` 和 `runtime/demo-admin.json`。
10. **注释与规范**：本轮涉及 Python 模块、类、函数、方法补齐中文 docstring 和事务/权限/并发注释；前端组件、请求与重试、样式、脚本、迁移和测试补充中文说明。项目 skill 增加注释要求，AGENTS.md 和交接模板一并交付。旧 M0–M4 和既有决策历史保留。

## 接手与回退

- **本机入口**：测试服务 `http://127.0.0.1:8766`；本轮启动了服务及每五秒独立维护。`tools/start-local.ps1 -TestProfile -Port 8766` 可重建并启动，已有构建可加 `-SkipBuild`。当前模式默认端口 8765。不要同时启动同一端口的服务。
- **配置**：`.env.local` 与 `runtime/` 不提交，连接参数及测试账号例外的环境变量见 `docs/LOCAL_RUNBOOK.md`。复制代码到另一机器不会自动创建本机账号或携带免码配置；明确选择合成模式后通过管理命令创建。
- **迁移步骤**：准备独立 MySQL，安装锁定依赖，执行 `manage.py migrate`（0001 结构，0002 锁/版本/不可改写触发器及流水关系）。若迁旧库：停旧服务写入，保留源 SQLite，确认 profile/空目标，先 dry-run，再显式导入，核对报告并登录/幂等重放，然后启用新写入。没有旧数据时直接初始化 Owner。
- **备份**：`python -m revival --test-profile backup <新目标.sql>`。仅在临时恢复核对通过后报告成功；目标已存在时拒绝。恢复仍需人工选择空库、停写和核对，不能覆盖现有资产历史。
- **回退**：停止新服务及维护，先保存已核对 MySQL 备份。如果迁移后没有新写入，可使用保留的旧代码及原 SQLite 恢复旧入口；存在新写入时先对账并保留新账号、流水、制裁、幂等和 outbox，不能直接切回旧 SQLite 丢掉新数据。必要的补偿追加关联记录，不能删除历史流水；不复活撤销会话。
- **测试例外撤销**：停服务，移除对应 `NZ_FIXED_TEST_*` 或 `NZ_PASSWORD_ONLY_TEST_*` 配置并重新启动；账号随后回到正常管理员 MFA 行为。私人 MFA 密钥保留于本机凭据文件，不发布。
- **下一步**：查看推送后的 Actions；正式迁移时执行真实源库停写导入验收。游戏接入继续等待原阶段所需证据。
